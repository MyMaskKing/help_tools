# Clash Verge 自动分组插件（ClashVergePlug.js）

> 一个丢进去就不用管的脚本：自动按**地区**给你建好测速组，节点多的话再按**协议**细分一层，同时把**国内节点**单独收进一个组。

---

## 一、这个脚本解决什么问题

机场（订阅）给的节点通常是一长串平铺的列表，几百个名字堆在一起，节点一多就完全没法用：

- 想找日本节点，得在一堆名字里翻；
- 香港、台湾、上海家宽这些**国内节点**混在国外节点里，测速时排在前面，很容易连到不该用的线路；
- 手动维护分组累，而且订阅一更新就全白干。

这个脚本在**每次加载订阅时**自动重排一遍，做三件事：

| 做的事 | 结果 |
| --- | --- |
| ① 按地区建组 | 日本 / 新加坡 / 韩国 / 美国 … 各一个自动测速组 |
| ② 地区组再按协议细分 | 例：`🇯🇵 日本自动` 下面自动生成 `🇯🇵 日本-SS`、`🇯🇵 日本-VMess`、`🇯🇵 日本-HY2` |
| ③ 国内节点单独归组 | 香港、台湾、中国内地节点全部进 `🇨🇳 国内自动`，不再混进"国外自动" |

它**只调整 proxy-groups（分组），不动你的节点、不动分流规则、不动端口和 DNS**，所以出问题把脚本删掉、重新应用一次订阅就完全恢复。

## 二、先认识 4 个名词（30 秒版）

| 名词 | 通俗解释 |
| --- | --- |
| **订阅（Profile）** | 机场给你的那条链接，里面是「节点列表 + 分流规则」的 YAML 文件 |
| **节点（proxy）** | 一个具体的服务器，名字由机场起，如 `🇯🇵 日本01 HY2` |
| **代理组（proxy-group）** | 一堆节点的"文件夹"，客户端里点它就是用这个文件夹里的节点 |
| **`main(config)`** | Clash Verge 脚本约定的入口函数，客户端把整份订阅配置交给它，它返回改好的配置 |

代理组有三种基本类型，脚本里都会用到：

- **`url-test`（自动测速）**：定时给组里所有节点测延迟，永远用最快的那个。
- **`fallback`（容灾/故障转移）**：按顺序用，第一个不通了才换第二个。速度不是最优，但最稳。
- **`select`（手动选择）**：你自己点，点了就固定用它。🚀 节点选择 就是这种。

## 三、原理：脚本到底干了什么

`main(config)` 拿到整份配置后，按下面 8 步依次处理，最后把配置还回去：

```
订阅 YAML
   │
   ├─① 取出所有节点名，扔掉假节点（剩余流量 / 官网 / 套餐 / 到期…）
   │
   ├─② 按 REGION_RULES 里的关键字匹配地区
   │      🇯🇵 日本  ← 名字含 日本 / 🇯🇵 / JP / Japan / 东京 / 大阪
   │      🇸🇬 新加坡 ← 名字含 新加坡 / 🇸🇬 / SG / Singapore
   │      …
   │
   ├─③ 每个地区按【协议】分类（协议从订阅里的 type 字段读，最可靠）
   │      日本: ss×3, vmess×2, hysteria2×3
   │
   ├─④ 数量够多就细分：
   │      🇯🇵 日本-SS    (url-test)
   │      🇯🇵 日本-VMess (url-test)
   │      🇯🇵 日本-HY2   (url-test)
   │      🇯🇵 日本自动   (url-test，成员是上面 3 个子组 → 自动选最快的那一类)
   │
   │   数量太少就不细分，直接  🇸🇬 新加坡自动 (url-test，平铺 2 个节点)
   │
   ├─⑤ 用 excludeCN 正则把节点切成两组
   │      命中 → 🇨🇳 国内自动（香港/台湾/内地…）
   │      未命中 → 🌍 国外自动（拿来做全局兜底）
   │
   ├─⑥ 拼出 🌍 国外容灾 (fallback)
   │      顺序 = 日本 → 新加坡 → 韩国 → 美国 → 国外自动
   │      日本全挂走新加坡，再挂走韩国…最后兜底到"全部国外节点"
   │
   ├─⑦ 新组全部排到旧组前面，写回 config["proxy-groups"]
   │
   └─⑧ 找到主入口 select 组（如 🚀 节点选择），把这几个自动组塞到最前面，
         这样你在客户端首页第一眼就能选到它们
```

### 关键判断：为什么要按「协议」细分

同一个国家往往有好几代协议混在一起：

- `SS` / `SSR`：老协议，兼容性最好，但被墙识别率也高；
- `VMess` / `VLESS`：主流，稳定性取决于机场线路；
- `Hysteria2` / `TUIC`：基于 QUIC，晚高峰和丢包环境下通常比 TCP 类协议快很多。

按协议分开后，你可以直接连 `🇯🇵 日本-HY2` 走性能最好的那类，而不用担心"日本自动"测速时选了个慢速的老协议节点。父组 `🇯🇵 日本自动` 则负责在几类之间自动挑最快的，两不耽误。

### 两种"自动"的区别

| 组 | 类型 | 行为 |
| --- | --- | --- |
| `🇯🇵 日本自动`（父组） | `url-test` | 在 3 个协议子组里比延迟，用最快的一类 |
| `🌍 国外容灾` | `fallback` | 严格按地区顺序，日本挂了才走新加坡，最抗封 |

> 如果你用的客户端版本对"组里套组"支持不好（现象：这个组显示为空或报错），把 `SETTINGS.regionParentType` 改成 `"fallback"` 即可。

### 匹配规则的两个细节（避免踩坑）

1. **短代码必须"独立出现"**。`US` 用普通的包含匹配会命中 `RUSSIA`、`AUS`，`HK` 会命中一堆奇怪缩写。脚本对 1–3 位纯字母/数字的关键字（`JP`/`US`/`HK`/`SG`…）做了边界判断，所以 `RUSSIA 测试节点` 不会被当成美国节点。
2. **协议优先读 `type` 字段**，只有当订阅里没写 `type` 时，才去节点名里猜（含 `hy2`/`vmess`/`vless` 等字样）。

## 四、最终会得到什么

以一份 30 个节点（日本 8 / 新加坡 2 / 韩国 4 / 美国 7 / 国内 5）的订阅为例，脚本跑完后分组是这样：

```
🇯🇵 日本-HY2        url-test      3 个节点
🇯🇵 日本-VMess      url-test      2 个节点
🇯🇵 日本自动        url-test      成员：日本-HY2 / 日本-VMess / 日本-SS
🇸🇬 新加坡自动      url-test      2 个节点（不够 6 个，不细分）
🇰🇷 韩国自动        url-test      4 个节点（不够 6 个，不细分）
🇺🇸 美国-VLESS      url-test      4 个节点
🇺🇸 美国-Trojan     url-test      3 个节点
🇺🇸 美国自动        url-test      成员：美国-VLESS / 美国-Trojan
🌍 国外自动         url-test      所有非国内节点
🇨🇳 国内自动        url-test      香港 / 台湾 / 内地节点
🌍 国外容灾         fallback      日本自动 → 新加坡 → 韩国 → 美国 → 国外自动
🚀 节点选择         select        ← 上面这些自动组已经被插到最前面
```

日常用的时候你只需要认识两个：**`🌍 国外自动`**（平时上网）和 **`🌍 国外容灾`**（感觉被限速/断流时切它）。

## 五、怎么用（Clash Verge Rev）

> 需要 **Mihomo（Clash Meta）内核**，Clash Verge Rev 默认就是。旧版 Clash 内核不支持部分协议，也不支持"组套组"。

### 方式 A：只给某一个订阅用（推荐）

1. 打开 Clash Verge Rev，进 **订阅 / Profiles** 页；
2. 在目标订阅上**右键 → 编辑脚本 / Edit Script**（有的版本叫"扩展脚本"）；
3. 把 `ClashVergePlug.js` 的**全部内容**粘进去，保存；
4. 回到订阅页，右键该订阅 → **使用 / 重新应用**（或点一下别的订阅再点回来，强制刷新）；
5. 进 **代理 / Proxies** 页，应该能看到 `🌍 国外自动`、`🇨🇳 国内自动` 等新分组。

### 方式 B：所有订阅都生效

**设置 / Settings → 全局扩展脚本 / Global Script**，把脚本粘进去，保存后重新应用任意订阅即可。

### 贴之前先做完这件事

脚本只是一个 JS 函数，粘贴时**不要**加 `export`、`module.exports`、`import`，也不要包 `<script>` 标签。文件内容就是：

```js
function main(config) {
    ...
    return config;
}
```

### 怎么确认它真的生效了

- 脚本里有 `console.log`，打开客户端的**日志**面板能看到 `[auto-group] 建组 🇯🇵 日本自动（3 个子组）` 这类输出；
- 更直接的办法：代理页分组数量变多了，且多出来的组名字带 🌍 / 🇨🇳 / `-SS` / `-HY2` 后缀。

## 六、配置项（想改行为只动 SETTINGS）

脚本开头的 `SETTINGS` 就是全部可调项：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `testUrl` | `https://cp.cloudflare.com/generate_204` | 测速地址。测速不准就换成 `http://www.gstatic.com/generate_204` |
| `interval` | `300` | 测速周期（秒），越小越灵敏、越耗流量 |
| `tolerance` | `80` | 允许延迟差（毫秒）。新节点只快 50ms 时不切换，避免来回跳 |
| `fallbackInterval` | `60` | 容灾组健康检查周期（秒） |
| `excludeCN` | 见文件 | **国内判定正则**。命中就进 `🇨🇳 国内自动`，同时从 `🌍 国外自动` 里剔除 |
| `subdivideMinNodes` | `6` | 地区节点数 ≥ 6 且协议 ≥ 2 种才按协议细分，否则平铺 |
| `regionParentType` | `"url-test"` | 地区父组类型。客户端不支持组套组时改成 `"fallback"` |
| `injectCNGroup` | `true` | 是否把 `🇨🇳 国内自动` 也塞进主入口 select |

### 加一个新地区

在 `REGION_RULES` 里照抄一行就行，**顺序就是容灾优先级**：

```js
"🇬🇧 英国自动": ["英国", "🇬🇧", "UK", "GB", "London", "伦敦"],
"🇩🇪 德国自动": ["德国", "🇩🇪", "DE", "Germany", "法兰克福"],
```

保存 → 重新应用订阅，`🇬🇧 英国自动` 和 `🇬🇧 英国-SS` 这类子组会自动出现。

### 地区判定优先级

`REGION_RULES` 从上到下依次匹配，**先匹配到就归这个地区**（不会重复入组）。所以关键字写得宽的地区要放在后面，免得抢走别的地区的节点。

## 七、常见问题

**Q1：粘贴保存后，代理页没有任何新分组。**

按顺序排查：

1. 订阅里有没有节点？节点全被黑名单（`剩余`/`流量`/`官网`/`订阅`/`套餐`/`到期`/`重置`）过滤掉了？看日志有没有"节点被黑名单全部过滤"；
2. 分组名是不是和订阅自带的完全重名？脚本对**同名组一律跳过**（这是刻意的，避免覆盖机场自带的分组）；
3. 是不是忘了重新应用订阅——脚本只在订阅加载时执行一次；
4. 内核是不是 Mihomo？旧 Clash 内核不支持 `hysteria2`/`tuic` 等，会整份配置校验失败。

**Q2：某个地区组里一个节点都没有 / 节点跑到了别的地区。**

说明关键字没命中。去订阅里复制该节点的完整名字，把里面的中文地名或 emoji 加进对应规则数组即可。注意 `JP`、`US` 这类短代码是**按独立单词匹配**的，`JP01` 能命中，`JPN01` 不会。

**Q3：香港节点为什么在 `🇨🇳 国内自动` 里？**

因为 `excludeCN` 里包含 `香港|HK|🇭🇰|台湾|TW|🇹🇼|中国|CN`。这类线路常用于国内落地/回国，所以统一归到国内组。如果你想让香港算"国外"，把 `香港|HK|Hong\s*Kong|🇭🇰` 从正则里删掉即可。

**Q4：`🇨🇳 国内自动` 有什么用？我不想让它出现在主入口。**

国内落地节点一般用来访问国内受限服务、给下载/游戏加速或做落地中转，不适合当翻墙出口。不想让它出现在 🚀 节点选择 里，把 `SETTINGS.injectCNGroup` 设为 `false`（组还会建，只是不注入入口）。

**Q5：`🇯🇵 日本自动` 显示为空 / 提示成员无效。**

你的客户端版本对"组里套组"支持不好。把 `SETTINGS.regionParentType` 改成 `"fallback"`，或者把 `subdivideMinNodes` 调大（比如 999）直接关掉细分。

**Q6：会不会覆盖我自己建的分组？**

不会。脚本只做三件事：追加新组、往主入口 select 组的 `proxies` **最前面插名字**、跳过所有同名组。原有分组的成员和顺序不动。

**Q7：怎么彻底卸载？**

删掉脚本内容，重新应用订阅。分组是每次实时生成的，不会残留在任何地方。

用 Node.js 跑一下，把打印出来的分组贴进任意 YAML 校验器检查，确认结构合法：

```js
const fs = require('fs');
const main = new Function(fs.readFileSync('./ClashVergePlug.js', 'utf8') + '\nreturn main;')();

const config = {
  proxies: [
    { name: '🇯🇵 日本01 SS', type: 'ss', server: 'x', port: 1 },
    { name: '🇯🇵 东京 HY2', type: 'hysteria2', server: 'x', port: 1 },
    { name: '🇭🇰 香港01', type: 'ss', server: 'x', port: 1 },
  ],
  'proxy-groups': [{ name: '🚀 节点选择', type: 'select', proxies: ['🇯🇵 日本01 SS'] }],
};

console.log(JSON.stringify(main(config)['proxy-groups'], null, 2));
```

## 九、结构速查

```
clash-verge-plug/
├── ClashVergePlug.js   # 脚本本体，整份粘进 Clash Verge 的扩展脚本
└── README.md           # 本文
```

脚本内部分区（改代码时按注释找）：

1. `SETTINGS` 全局配置
2. `NAME` 固定组名
3. `REGION_RULES` 地区关键字（顺序 = 容灾优先级）
4. `PROTOCOL_LABEL` / `PROTOCOL_ORDER` 协议显示名与优先级
5. 工具函数（关键字匹配、协议识别）
6. 读节点 + 黑名单过滤
7. 组构造器（`url-test` / `fallback`）
8. `createRegion()` 建地区组（含协议细分）
9. 遍历地区
10. 国内 / 国外切分
11. `🌍 国外容灾`
12. 合并分组
13. 注入主入口 select
